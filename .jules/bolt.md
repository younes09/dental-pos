## 2024-05-24 - N+1 Correlated Subqueries in SELECT clause
**Learning:** In the `api/reports.php` file, calculating aggregates (like `total_orders` and `total_spent`) using correlated subqueries directly within the `SELECT` clause (e.g., `(SELECT SUM(total) FROM sales WHERE customer_id = customers.id)`) causes severe N+1 performance bottlenecks. The database executes these subqueries for every single row returned by the outer query, leading to exponential execution time as the dataset grows.
**Action:** When aggregating related data, replace correlated subqueries in the `SELECT` clause with a `LEFT JOIN` on an aggregated derived table (e.g., `LEFT JOIN (SELECT customer_id, SUM(total) as total_spent FROM sales GROUP BY customer_id) s ON c.id = s.customer_id`). Use `COALESCE` to handle `NULL` values when there are no related records.
