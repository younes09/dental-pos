## 2024-10-24 - N+1 Correlated Subqueries in Unbounded List Endpoints
**Learning:** In PHP/MySQL applications using PDO, unbound list endpoints (e.g., fetching all products or all sales history) suffer extreme performance degradation (N+1 query problem) when the `SELECT` clause contains correlated subqueries. While derived tables (subqueries with `LEFT JOIN` and `GROUP BY`) solve this by allowing the database to aggregate data more efficiently in bulk, they can actually *hurt* performance if the query is heavily filtered (e.g., `WHERE customer_id = ?`), as standard SQL engines cannot always push the filter down into the derived table, causing full table scans.
**Action:** When refactoring correlated subqueries in endpoints that support both filtered and unbounded requests, implement a conditional logic branch: retain the correlated subqueries when strict index-backed filtering is active, but switch to materialized derived tables for unbounded or lightly filtered lists to eliminate the N+1 bottleneck.
