## 2024-09-19 - Replacing N+1 Correlated Subqueries with LEFT JOIN on Derived Tables
**Learning:** In list endpoints fetching all rows (like customers or suppliers lists), using correlated subqueries in the SELECT clause (e.g., `(SELECT SUM(total) FROM sales WHERE customer_id = c.id)`) acts like an N+1 query problem executing per row. While standard indexes help, performance degrades heavily with large row counts. A better approach is to `LEFT JOIN` on an aggregated derived table grouped by the foreign key (e.g., `LEFT JOIN (SELECT customer_id, SUM(total) FROM sales GROUP BY customer_id)`). This computes the aggregates once for all rows. However, a major caveat exists: for dynamically filtered list queries (e.g., `WHERE c.id = ?`), standard MySQL engines cannot easily push the outer `WHERE` condition into the aggregated derived table, potentially leading to a full table scan on the derived query anyway.
**Action:** Replace correlated subqueries with `LEFT JOIN` on grouped derived tables for unbounded list endpoints that fetch multiple rows (`api/customers.php`, `api/suppliers.php`, `api/reports.php`). For queries with specific single-row filters (like fetching details for a specific customer or product), retain the indexed correlated subqueries, or ensure the specific `WHERE` clause is duplicated inside the derived table's `SELECT`.
