## 2023-10-25 - N+1 Subquery Conversion to Derived Joins
**Learning:** In unbounded list endpoints (like customers or products), using correlated subqueries in the `SELECT` clause (e.g., `(SELECT ... WHERE fk = parent.id)`) forces standard SQL engines to execute the subquery for every returned row, leading to an O(N) query explosion (N+1 anti-pattern) that cripples performance as datasets grow.
**Action:** When calculating aggregations (like totals, last visits) across an entire table for a list endpoint, convert the correlated subqueries into a single `LEFT JOIN` onto a derived table grouped by the parent's foreign key (e.g., `LEFT JOIN (SELECT fk, MAX(val) FROM t GROUP BY fk) agg ON parent.id = agg.fk`), and use `COALESCE` in the main `SELECT` to safely handle missing relations.
